## 1. 背景と完了段階

当初の課題は、`31_分析レポート表示項目` でONの分析軸が、求人情報のないレポートでもカスタム分析プルダウンに現れ、選択後に集計不能になっていたこと。

- **第1段階（Pages v30.44）完了**：分析軸に「設定上ON」と「保存済み元データとして利用可能」の2条件を導入した。勤務地・居住都道府県一致を求人CSV突合非依存にした。
- **第2段階（Pages v30.45）完了**：求人CSVと突合できなくても、応募CSV内に埋め込まれた求人情報を分析用求人マスタに補完し、利用可能な求人系軸を拡大した。
- **本整理では実装変更なし**。本番GAS／Workerの稼働バージョンや、個社データでの全ケース検証を保証しない。

## 2. 利用可能性の共通ルール

カスタム分析の候補は基本的に次の両条件を満たす軸に限定する。

1. `31_分析レポート表示項目` に対応する設定がON。
2. 保存済みデータ・ヘッダー・マスタ等が、その軸の利用可能条件を満たす。

例外として **給与区分** は独立した31項目を直接参照するのではなく、時給／日給／月給／年収の下限軸の表示条件と連動して候補に入る。

利用可能性は **期間・年齢などの現在の表示フィルターを適用する前の保存済みデータ** から判定する。そのため、表示期間だけ0件になっても候補自体は消さず、集計結果が0件になり得る。

判定は `analysis-core.js` の `buildAnalysisSourceCapabilities()`、`analysisAxisAvailable()`、`customAxisOptions()` が担当する。基本分析も可能な範囲で共通判定を利用する。「サイドバーのラベル文字列を抽出してプルダウンへ転用する」仕組みではない。

## 3. カスタム分析軸の仕様一覧（合計30種類）

### A. 応募情報で利用できる軸（11）

| 軸 | 現行の利用可能条件 | 解釈上の注意 |
|---|---|---|
| 対応状況 | 応募DataStoreが1件以上 | 応募CSVの対応状況。欠損値は（未設定） |
| 応募年月 | 応募DataStoreが1件以上 | 応募日時から生成 |
| 応募媒体 | 応募DataStoreが1件以上 | A/Bの媒体列を正規化 |
| 性別 | 応募DataStoreが1件以上、かつapplicationDataに「性別」ヘッダー | 男性／女性／未回答／不明。旧データでヘッダーがなければ非表示 |
| 氏名文字種区分 | 応募DataStoreが1件以上 | 氏名の文字種区分。欠損値は（不明） |
| 居住都道府県 | 応募DataStoreが1件以上 | 住所由来。全件不明でも候補になり得る |
| 企業ID | 応募DataStoreが1件以上、かつ42_企業IDマスタで表示名が1件以上有効 | 一部のIDに表示名がなくても候補になり得る |
| 月内応募日 | 応募DataStoreが1件以上 | 応募日と設定バケット幅を使用 |
| 応募曜日 | 応募DataStoreが1件以上 | 月～日と不明 |
| 応募時間帯 | 応募DataStoreが1件以上 | 応募時刻と設定バケット幅を使用 |
| 勤務地・居住都道府県一致 | 応募DataStoreが1件以上、かつ一致／不一致が1件以上有効 | 応募CSV由来の一致結果を利用。求人CSV突合は不要 |

「応募DataStore」は `applicationData` の保存済みレコードを指す。応募CSV単体で成立する軸でも、ヘッダーやマスタの追加条件が存在するものは上表の条件を優先する。

### B. 求人CSV／応募CSV内の求人情報の双方から利用できる軸（8）

| 軸 | 現行の利用可能条件 | 解釈上の注意 |
|---|---|---|
| 職種 | jobAnalysisMasterの「職種」に非空値 | 求人CSV優先、応募CSV内の求人情報で補完 |
| 雇用形態 | jobAnalysisMasterの「雇用形態」に非空値 | 同上 |
| 求人勤務地名称 | jobAnalysisMasterの「求人勤務地名称」に非空値 | 空欄のみなら候補外 |
| 勤務地都道府県 | jobAnalysisMasterの「勤務地都道府県」に非空値 | 勤務地住所からの都道府県抽出も対象 |
| 募集背景 | jobAnalysisMasterの「募集背景」に非空値 | 入力側に該当情報がなければ候補外 |
| 仕事名KW | 仕事名の非空値、かつ40_仕事名KWマスタに項目あり | KW未該当の結果は（該当なし） |
| 仕事名フルKW | 仕事名の非空値、かつ40_仕事名KWマスタに項目あり | 複数KWの結合。未該当は（該当なし） |
| 求人備考1行目 | jobAnalysisMasterの「求人備考」に非空値 | 備考の先頭行をカテゴリ化 |

ここでの求人情報は `jobAnalysisMaster` を指す。`求人分析情報ソース` が `JOB_CSV` の行だけでなく、`APPLICATION_EMBEDDED` の行も利用できる。**単に求人CSVファイルがあるかではなく、分析に使う値が保存されているか**で判定する。

### C. 求人CSVを必要とする軸（11）

| 軸 | 現行の利用可能条件 | 解釈上の注意 |
|---|---|---|
| 給与区分 | jobAnalysisMasterに給与区分の非空値 | カスタム専用。給与下限軸のうち表示設定ONかつ利用可能なものが候補に入る場合に追加 |
| 時給下限 | JOB_CSV由来の「給与区分」が時給の求人あり | 金額が欠損／無効なら（給与下限なし）を表示することがある |
| 日給下限 | JOB_CSV由来の「給与区分」が日給の求人あり | 同上 |
| 月給下限 | JOB_CSV由来の「給与区分」が月給の求人あり | 同上 |
| 年収下限 | JOB_CSV由来の「給与区分」が年収の求人あり | 同上 |
| 求人原稿文字数 | JOB_CSV由来の数値型「求人原稿文字数」が存在 | 応募CSVの仕事内容だけから再計算しない |
| メイン画像有無 | JOB_CSV由来の求人分析行が存在 | 全求人が画像なしでも「なし」の分析は可能 |
| 求人画像枚数 | JOB_CSV由来の求人分析行が存在 | 画像0枚も有効な分析値 |
| TOP画像ファイル名 | JOB_CSV由来の「メイン画像ファイル名」に非空値 | ファイル名別の集計 |
| 求人動画有無 | JOB_CSV由来の求人分析行が存在 | 動画なしも有効な分析値 |
| Indeed求人タグ数 | JOB_CSV由来の求人分析行が存在 | タグ0個も有効な分析値 |

`JOB_CSV` 由来の求人行には、v30.44以前の互換形式（ソース列なし）も含む。上表の「求人行あり」条件は必ずしも各行の画像・動画・タグの値が非空であることを要しない。0件／なしを分析するため。

## 4. データの優先順位・突合率の意味

- **JOB_CSV**：求人CSVと突合できた求人。給与・原稿文字数・画像・動画・Indeedタグを含むすべての対応分析が可能。
- **APPLICATION_EMBEDDED**：求人CSVの突合がないが、応募CSVに仕事名／職種／雇用形態／求人勤務地名称／勤務地／求人備考／募集背景など利用可能な値がある求人。B群の対応属性だけを補完する。
- 求人CSVが突合済みの場合、対応する主要属性は求人CSVの非空値を優先し、その値が空欄なら応募CSV内の求人情報で補う。
- 同じ求人キーに属する複数の応募から得られた非空値は統合し、最初の応募行だけに依存しない。
- `求人データ突合フラグ` と `求人データ突合率` は **実際の求人CSVとの突合** を意味し、応募CSVからの補完によって増やさない。
- カスタム分析の集計対象集合は、選択軸に応じて `application`（全応募）／`jobAnalysis`（求人分析情報あり応募）／`jobCsv`（求人CSV突合応募）となる。混合軸を選ぶ場合は **jobCsv > jobAnalysis > application** の順に狭い集計対象を使う。
- 行軸は最大3つ。行・列を含め、同一軸を重複選択できない。
- `（求人情報なし）`、`（未設定）`、`（不明）`、`（該当なし）`、`（給与下限なし）` は同義ではない。欠損・未突合・KW非該当・金額未登録などを区別する。

## 5. 入力CSVの正規化（前提）

- Pages v30.43でCSV_A／CSV_Bを **ファイルごとに文字コード判定・ヘッダー形式判定・行単位canonical化** して、従来ETLの前段へ渡す。
- UTF-8 BOM／有効なUTF-8を優先し、それ以外はShift_JIS/CP932系としてデコードする。単純な「BOMなし＝Shift_JIS固定」ではない。
- CSV_Aの `お仕事NO`、CSV_Bの `応募先企業ID`／`応募日`／`応募者名`／`応募媒体名`／`MAIL` などを共通項目へ統一する。
- CSV_Bに既存の `都道府県` と `住所` があるため、単純なヘッダーaliasによる重複を避ける。居住都道府県は住所からの抽出を含む。
- 性別は「男／男性→男性」「女／女性→女性」「未回答→未回答」「不明／空欄→不明」とする。
- 求人CSV側は既存の処理経路を維持する。

## 6. 確認すべき代表ケース（テスト計画／実施済みとは限らない）

| ケース | 期待される動作 |
|---|---|
| CSV_Aのみ、求人CSVなし | A群は利用可能。B群は埋め込み属性に有効値がある場合のみ。C群は不可 |
| CSV_Bのみ、求人CSVなし | CSV_B内の職種／雇用形態／勤務地等をB群で使用可能 |
| 応募CSV_A＋Bを同時投入 | ファイル単位で正規化。canonical後に統合し、性別等のカテゴリを分裂させない |
| 求人CSVあり＋同じ求人の応募CSV埋め込み情報あり | 求人CSVの非空値を優先。求人CSVの空欄は互換属性に限り補完 |
| 求人CSV突合が0件だが応募CSV埋め込み求人情報がある | B群の該当軸を表示でき、求人データ突合率は0%のまま |
| 31でOFF | ソースデータがあってもカスタム候補から除外 |
| 元データに属性がない | 当該B群・C群の軸を候補に出さない |
| 表示期間／年齢条件により結果0件 | 元データで利用可能なら軸は候補に残る |
| 古い `applicationData` に性別ヘッダーなし | 性別の基本分析・カスタム軸を出さない |
| 都道府県一致が取得不能 | 不明を誤って不一致としない。新ETLで両者が解決できなければ空欄 |
| 給与区分はあるが下限額が空欄 | 給与下限軸の候補判定と金額カテゴリの欠損判定を区別 |
| 求人CSVの画像・動画・タグがゼロ | 求人CSV由来行があれば「なし」／0の集計が可能 |

※ 上表は確認観点であり、すべてを今回再実行した結果ではない。

## 7. 現時点での保留・改善候補（未実装依頼）

1. A群の一部は「応募レコードあり」だけで候補となる。居住都道府県が全件不明でも候補になり得るため、欠損を指標として残すか非表示にするかは実運用で判断する。
2. 給与下限は該当する給与区分の求人が存在すれば候補になり得る。下限金額が全件未入力の場合の表示方針は必要になった時点で検討する。
3. CSV_Bの入力によって取得できる求人情報の範囲は実ファイルの列・入力率に依存する。特に勤務地名称や募集背景が空欄なら、その軸を無理に有効化しない。
4. 大きな設計変更は実際の個社レポートで不一致・誤解が確認できた後に、具体例と期待動作を起点として扱う。
